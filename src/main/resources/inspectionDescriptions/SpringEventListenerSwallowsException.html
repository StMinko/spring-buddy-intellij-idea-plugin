Reports @EventListener / @TransactionalEventListener methods whose body catches a broad exception type (Exception, Throwable, RuntimeException) and only logs without rethrowing.

Spring then never sees the failure: publishers can't react and transactional rollback rules won't trigger. Catch a more specific exception and handle it explicitly, or log and rethrow.

@TransactionalEventListener methods are reported only for phase = BEFORE_COMMIT. The other phases (including the default AFTER_COMMIT) run after the transaction finished, and Spring catches and logs whatever they throw, so a local catch-and-log loses nothing.
