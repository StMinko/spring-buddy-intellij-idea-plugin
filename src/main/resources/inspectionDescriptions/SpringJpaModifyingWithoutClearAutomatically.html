Reports Spring Data JPA @Modifying annotations that don't set clearAutomatically = true.

Without it, entities cached in the persistence context can become stale after a bulk update or delete query, leading to subtle read-after-write bugs. The quick-fix adds the attribute.

For methods with callers, the inspection reports only when the same scope reads an entity of the bulk query's type before the modifying call and reads it again afterward. The scope is the enclosing method or the innermost TransactionTemplate or TransactionOperations callback. The entity type comes from the JPQL update/delete query or the repository's first generic type argument and is matched by simple class name. An entity whose getId() is passed to a parameter the JPQL query excludes with alias.id <> :param is not counted, because the bulk query cannot touch its row. Calls across methods are not followed; uncalled methods and cases without a determinable entity type remain reported.
