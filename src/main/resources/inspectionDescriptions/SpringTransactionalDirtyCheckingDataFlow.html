Reports @Transactional methods that appear to load an entity from a repository and then mutate it without declaring readOnly = true.

In a regular JPA transaction, dirty checking persists changes to managed entities when the transaction commits, even if the method never calls save(). Marking read operations as @Transactional(readOnly = true) communicates intent and avoids accidental dirty checking.

Methods that call a write operation (save, saveAndFlush, delete*, persist, merge, flush, ...) or load an entity through a repository method annotated with a write lock (@Lock(PESSIMISTIC_WRITE), *_FORCE_INCREMENT) are treated as intentional writes and are not reported.

The quick-fix adds readOnly = true to the transactional annotation.
