Reports setParameter bindings that pass a String (or other non-association value) to a named parameter that the query compares against an association-typed path (a @ManyToOne/@OneToOne field of the query's entity). This is a runtime-breaking error: Hibernate 6 fails the query with a QueryArgumentException when it executes.

Hibernate 6 validates the parameter binding type when a query executes. Binding a String to an association path fails at runtime with org.hibernate.QueryException: Argument [x] of type [java.lang.String] did not match parameter type [AssociationEntity] (a QueryArgumentException). Older Hibernate versions silently coerced the value, so migrated applications typically only discover this in production.

This typically happens after a migration turns a formerly String-typed field into an entity reference. Consider an entity whose mandant field became an association to a Mandant entity with the String @Id mandant: 

// broken: binds a String to the association path
em.createQuery("from LegalEntity p where p.mandant=:mandant", LegalEntity.class)
  .setParameter("mandant", "BMW")            // QueryArgumentException at runtime

// fixed: navigate the association to its String @Id
em.createQuery("from LegalEntity p where p.mandant.mandant=:mandant", LegalEntity.class)
  .setParameter("mandant", "BMW")

The inspection walks the fluent createQuery(...).setParameter(...) call chain, resolves every compared path (p.mandant, le.mandant for a left join v.legalEntity le) against the entity model, and flags bindings whose argument type does not match the association. Binding the association value itself is reported as valid.
