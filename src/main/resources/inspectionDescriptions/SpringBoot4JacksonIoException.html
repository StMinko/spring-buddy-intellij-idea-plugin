Reports an IOException catch whose try block calls into com.fasterxml.jackson.

Jackson 3 made all mapper methods unchecked and removed the checked IOException/JsonProcessingException throws, so the IOException catch no longer covers the Jackson calls. Deserialization failures surface as an unhandled JacksonException instead of being handled by the catch block. Catch tools.jackson.core.JacksonException (or widen to Exception when other checked calls share the block).

Quick fix rewrites the catch to catch (IOException | JacksonException ex). It is offered only when the catch block keeps compiling with the wider parameter type: the parameter is only rethrown, used as the receiver of a Throwable method, or passed where a Throwable, Exception or Object is expected, and no other catch of the same try handles a Jackson exception.
