Reports calls on Jackson 2 types whose method signature changed or disappeared in Jackson 3 (Spring Boot 4). The renames are verified against the Jackson 3 jars:
  • JsonGenerator: writeFieldName() → writeName(), writeObjectField() → writePOJOProperty(), the *Field/*FieldStart family to the *Property family, writeObject() → writePOJO()
  • JsonParser: getCurrentToken()/getCurrentName() and the other getCurrent* accessors to the current* accessors, nextFieldName() → nextName(); readValuesAs() was removed without a counterpart
  • ObjectReader/ObjectWriter: withType() → forType(); readValue(value, type) on ObjectReader becomes forType(type).readValue(value)
  • JsonNode: isContainerNode() → isContainer(), findValuesAsText() → findValuesAsString(), fieldNames() → propertyNames(), fields()/elements() → properties()/values(), with() → withObject()
  • ObjectMapper: getSerializationConfig()/getDeserializationConfig() → serializationConfig()/deserializationConfig(), writerWithType() → writerFor(); configuration setters such as registerModule(), setSerializationInclusion() and setDateFormat() moved behind JsonMapper.builder()

Spring Boot 4 upgrades to Jackson 3, so the old calls no longer compile. Methods that merely moved behind the builder API are reported without a quick fix, because the replacement restructures how the mapper is built.

Quick fix rewrites the call in place for the mechanical renames.
